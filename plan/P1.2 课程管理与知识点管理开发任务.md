# Mastery Lab — P1.2 课程管理与知识点管理开发任务

现在开始执行 Mastery Lab 的 P1.2 阶段。

P0 和 P1.1 已经完成。本次请基于现有项目继续开发，不要重新初始化项目，不要推翻已有架构。

你的角色是项目全栈开发工程师，需要实际修改代码、运行项目、完成测试，而不是只输出开发方案。

## 一、本阶段目标

建立完整的课程管理体系。

用户通过 P1.1 导入教材并创建课程后，可以在课程中心管理课程，进入课程详情查看章节和知识点，维护学习目录，并记录每个知识点的学习状态。

本阶段暂时不开发完整 AI 教学教室、AI 教学状态机和代码运行环境。

## 二、开发前检查

开始之前：

1. 阅读 docs/PRD.md、docs/ARCHITECTURE.md、docs/DATABASE.md、docs/DEVELOPMENT_PLAN.md。
2. 检查 P1.1 实际实现的页面、API、数据库模型。
3. 确认课程、章节、知识点的数据关系。
4. 检查现有功能是否存在问题。
5. 在现有基础上扩展，不要重复创建已有功能。

如果发现 P1.1 的数据结构不满足本阶段需求，先分析原因，设计兼容性调整方案，不允许直接删除或重建用户数据。

## 三、课程中心

完善课程中心页面。

### 1. 课程列表

展示：
- 课程名称
- 课程简介
- 教材来源
- 章节数量
- 知识点数量
- 学习进度
- 最近学习时间
- 创建时间

支持：
- 搜索课程
- 按创建时间排序
- 按最近学习时间排序
- 继续学习
- 查看课程详情
- 编辑课程信息
- 删除课程

空状态需要有明确的教材导入入口。

### 2. 课程操作

支持：
- 修改课程名称
- 修改课程简介
- 更换课程封面或图标（如果现有设计支持）
- 查看原始教材信息
- 删除课程

删除课程必须二次确认，并妥善处理关联的章节、知识点和学习记录。

## 四、课程详情

新增或完善课程详情页面。

页面需要包含：

1. 课程基本信息
2. 学习进度概览
3. 章节目录
4. 知识点列表
5. 学习状态
6. 最近学习记录

章节目录采用清晰的树形结构。

支持：
- 展开和折叠章节
- 点击知识点查看详情
- 显示章节下的知识点数量
- 显示每个知识点的学习状态
- 显示当前课程整体学习进度

课程详情页面不能只是静态展示，所有数据必须来自后端真实接口。

## 五、章节管理

支持用户维护课程章节：

- 新增章节
- 修改章节名称
- 修改章节简介
- 删除章节
- 调整章节顺序
- 展开和折叠章节

删除章节前需要确认。

删除章节时，明确处理其下的知识点和相关学习记录，避免产生孤立数据。

章节排序必须持久化，刷新页面后顺序不变。

## 六、知识点管理

支持用户维护知识点：

- 新增知识点
- 修改知识点名称
- 修改知识点简介
- 修改知识点正文
- 删除知识点
- 调整知识点顺序
- 查看知识点来源章节

知识点需要保留与章节的关联关系。

知识点内容支持 Markdown 展示。

注意：本阶段只做知识点内容管理，不开发 AI 自动教学。

## 七、学习状态管理

为每个知识点建立学习状态。

建议状态：

- NOT_STARTED：未学习
- IN_PROGRESS：学习中
- COMPLETED：已完成
- REVIEW：待复习

支持：
- 手动调整学习状态
- 查看不同状态的知识点数量
- 根据状态计算课程学习进度
- 章节进度统计
- 刷新页面后状态不丢失

掌握度和 AI 评估机制留到后续阶段，不要在本阶段虚构掌握度。

学习进度计算规则必须统一，并在代码和文档中说明。

## 八、后端 API

检查现有接口后补充缺失接口。

至少覆盖：

课程：
- 获取课程列表
- 获取课程详情
- 修改课程信息
- 删除课程

章节：
- 获取课程章节
- 创建章节
- 修改章节
- 删除章节
- 调整章节排序

知识点：
- 获取知识点列表
- 获取知识点详情
- 创建知识点
- 修改知识点
- 删除知识点
- 调整知识点排序

学习状态：
- 获取课程学习进度
- 更新知识点学习状态

要求：
- 沿用现有 API 路由和统一响应结构。
- 参数校验完整。
- 处理不存在的课程、章节和知识点。
- 处理非法关联关系。
- 不允许通过修改 ID 操作其他课程的数据。
- 更新排序时保证数据一致性。
- 删除操作使用合理的数据库事务。

## 九、界面设计要求

延续 P0 已有的深色视觉风格。

要求：
- 专业、简洁、现代。
- 适配桌面端。
- 避免传统后台管理系统风格。
- 不要堆砌统计卡片。
- 课程目录需要清晰、易浏览。
- 知识点状态要容易识别。
- 操作入口明确，避免过多弹窗。
- 页面布局保持统一。

重点优化课程详情页的阅读体验和目录管理体验。

## 十、测试要求

使用真实数据库和真实 API 验证：

1. 创建课程后能在课程中心看到。
2. 能打开课程详情。
3. 能新增、修改、删除章节。
4. 能调整章节顺序。
5. 能新增、修改、删除知识点。
6. 能调整知识点顺序。
7. 能修改知识点学习状态。
8. 课程进度统计正确。
9. 刷新页面后数据和顺序仍然存在。
10. 删除课程后关联数据正确处理。
11. P0 模型配置功能仍然正常。
12. P1.1 教材导入和课程解析功能仍然正常。

不要只做前端模拟数据测试。
