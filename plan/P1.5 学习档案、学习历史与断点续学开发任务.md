# 三、学习历史记录

建立完整的学习历史记录。

每次用户进入课程学习时，能够记录一次学习活动。

至少记录：

- 学习活动 ID。
- 课程 ID。
- 知识点 ID。
- 学习会话 ID。
- 开始时间。
- 结束时间。
- 实际学习时长。
- 完成的教学阶段。
- 最终学习结果。
- 用户尝试次数。
- 使用提示次数。
- 创建时间。

需要支持：

1. 查询最近学习记录。
2. 按课程查看学习历史。
3. 按时间查看学习历史。
4. 查看某次学习的详细过程。
5. 查看该次学习完成了哪些知识点。
6. 查看学习过程中的错误和补讲记录。

时间统计必须准确。

不能简单使用页面打开到关闭的时间作为有效学习时长。

需要考虑：

- 用户切换页面。
- 浏览器关闭。
- 本地服务中断。
- 长时间无操作。
- 重复进入同一知识点。
- 会话恢复。

建议采用学习活动心跳或有效操作时间累计的方式计算学习时长，并设置合理的空闲超时规则。

# 四、断点续学

这是本阶段最重要的功能之一。

用户离开学习教室时，必须保存当前学习状态。

需要恢复：

- 当前课程。
- 当前章节。
- 当前知识点。
- 当前学习会话。
- 当前教学阶段。
- 当前阶段状态。
- 历史师生对话。
- 最近一次用户回答。
- 当前 CHECK、PAIR、VERIFY 的尝试次数。
- 已使用的提示次数。
- 当前阶段的教学内容。
- 尚未完成的任务。

以下情况都必须能够恢复：

1. 用户刷新浏览器。
2. 用户关闭学习教室。
3. 用户关闭浏览器。
4. 本地后端服务重启。
5. 电脑重新启动后重新打开应用。

恢复规则：

- 如果当前知识点没有完成，继续原来的知识点。
- 如果当前教学阶段没有完成，继续原来的阶段。
- 如果当前正在等待用户回答，不要重新提出一个新问题。
- 如果用户已经完成 VERIFY，不要重复要求验证。
- 如果当前知识点已经完成，恢复到下一个合理学习位置。
- 如果用户主动选择重新学习，才重新开始教学。

恢复时不能重复创建学习会话。

需要保证数据持久化和状态一致性。

# 五、知识掌握档案

为每个知识点建立基于实际学习证据的掌握档案。

建议掌握状态：

- NOT_STARTED：未接触。
- INTRODUCED：已接触。
- UNDERSTANDING：理解中。
- GUIDED_PRACTICE：引导练习中。
- INDEPENDENT：独立完成。
- NEEDS_REVIEW：需要复习。

状态更新规则：

NOT_STARTED：
尚未开始学习。

INTRODUCED：
已经完成知识讲解或案例演示。

UNDERSTANDING：
正在进行理解检查，或者尚未稳定通过。

GUIDED_PRACTICE：
已经进入师生共同实践。

INDEPENDENT：
通过独立验证，且没有依赖大量提示。

NEEDS_REVIEW：
验证失败、用户反复出错，或需要针对性复习。

要求：

1. 掌握状态必须与 P1.4 教学状态机保持一致。
2. 不允许 AI 随意修改掌握状态。
3. 必须有实际学习记录作为状态变化依据。
4. 一次答对不能直接认定为长期掌握。
5. 用户重新学习时不能丢失之前的历史证据。
6. 允许掌握状态根据后续学习情况发生变化。
7. 保留状态变更历史。

在课程详情页和学习档案页展示知识点掌握情况。

# 六、错题与薄弱点管理

建立错题和薄弱点记录功能。

记录来源：

- CHECK 阶段错误回答。
- PAIR 阶段实践错误。
- VERIFY 阶段验证失败。
- AI 识别到的典型理解偏差。

每条记录至少包括：

- 记录 ID。
- 课程 ID。
- 知识点 ID。
- 学习会话 ID。
- 原始问题。
- 用户回答。
- 正确解释或参考答案。
- 错误原因。
- AI 提供的纠正讲解。
- 记录时间。
- 当前处理状态。

支持：

1. 查看全部错题。
2. 按课程筛选。
3. 按知识点筛选。
4. 按错误类型筛选。
5. 查看完整错误上下文。
6. 标记已经理解。
7. 重新练习。
8. 查看历史错误次数。

重要：

不要把用户所有提问都记录成错题。

只有真正的错误回答、实践错误或验证失败，才应创建错题记录。

对于同一知识点反复出现的相同错误，可以归并为一个薄弱点，同时保留每次错误发生的历史。
