现在开始 Mastery Lab 的 P1 阶段。

P0 已经完成，请以当前项目代码为基础继续开发，不要重新初始化项目，不要推翻现有架构。

## 一、当前任务

本次只开发 P1.1：教材导入与课程解析。

暂时不要开发完整 AI 教学教室、代码执行器和复杂学习评估系统。

## 二、功能要求

### 1. 教材导入

支持以下文件：
- Markdown（.md）
- PDF（.pdf）

要求：
- 支持文件选择和拖拽上传。
- 显示文件名称、大小和类型。
- 显示解析进度。
- 能够处理空文件、损坏文件和不支持的文件。
- 原始教材保存在本地 data/courses 目录下。
- 不得将教材上传到外部服务器。

### 2. 教材解析

Markdown：
- 解析一级至六级标题。
- 提取章节和子章节。
- 提取代码块及其语言标识。
- 保留正文内容和标题层级。
- 尽可能识别知识点。

PDF：
- 提取文本内容。
- 尽可能保留章节结构。
- 识别代码片段。
- 对扫描版 PDF，如果当前版本无法识别文字，明确提示用户，不得伪造解析结果。

### 3. 课程结构预览

解析完成后进入课程结构预览页面。

需要展示：
- 课程名称。
- 教材文件。
- 章节目录。
- 章节下的知识点。
- 知识点简介。
- 代码示例数量。

允许用户：
- 修改课程名称。
- 修改章节名称。
- 修改知识点名称。
- 删除不需要的章节或知识点。
- 调整章节顺序。
- 添加知识点。

注意：AI 生成的学习路线只是建议，必须经过用户确认才能创建正式课程。

### 4. 课程创建

用户确认后：
- 创建课程记录。
- 保存课程目录。
- 保存知识点。
- 记录教材来源。
- 保存原始文件路径。
- 设置课程创建时间和更新时间。
- 初始化知识点学习状态为未学习。

### 5. 课程中心页面

新增课程中心页面。

需要支持：
- 课程列表。
- 课程封面或简洁图标。
- 课程名称。
- 教材类型。
- 知识点总数。
- 学习进度。
- 最近学习时间。
- 继续学习入口。
- 课程删除。

暂时不需要复杂的课程市场和社交功能。

## 三、数据设计

先检查现有 SQLAlchemy 模型和数据库结构。

在现有结构上合理扩展，至少考虑：

Course：
- id
- title
- description
- source_file
- source_type
- status
- created_at
- updated_at

Chapter：
- id
- course_id
- title
- description
- sort_order

KnowledgePoint：
- id
- chapter_id
- title
- description
- content
- sort_order
- mastery_level
- learning_status

具体字段可以根据现有项目规范调整。

要求：
- 关联关系正确。
- 删除课程时妥善处理关联数据。
- 不得破坏 P0 已有数据库和模型配置功能。
- 数据库结构变更必须有明确的迁移或兼容方案。

## 四、界面设计

沿用 P0 已有的视觉风格。

要求：
- 深色主题。
- 简洁、专业。
- 桌面端优先。
- 不要做成传统后台管理系统。
- 不要堆砌卡片。
- 重点突出教材导入、课程目录和学习路线。
- 保持现有侧边栏和顶部导航一致。

## 五、开发约束

1. 先阅读现有代码和 P0 文档。
2. 不要随意更换技术栈。
3. 不要删除或重写已有功能。
4. 不要把教材内容硬编码在前端。
5. 文件处理和解析放在后端。
6. 所有用户文件操作必须限制在允许的数据目录内，防止路径穿越。
7. 对异常情况提供明确提示。
8. 不要为了 AI 解析而强制依赖某个特定模型。
9. 优先保证 Markdown 和普通文本 PDF 的解析可靠性。
10. 不得虚构测试结果。

## 六、验收测试

至少验证：

1. 导入一个 Markdown 文件。
2. 能正确识别多级标题。
3. 能提取代码块。
4. 能导入普通文本 PDF。
5. 能预览课程结构。
6. 能修改章节和知识点。
7. 能调整顺序。
8. 能确认并创建课程。
9. 关闭并重新启动后课程仍然存在。
10. 删除课程后关联数据得到正确处理。

请使用真实测试文件验证，不要只做静态页面。
